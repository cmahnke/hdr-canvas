# checkHDRBitDepth() → {boolean}

Check if the supported bit depth is larger then 8 Note that this is only a heuristic: browsers commonly report a colorDepth of 24 even on HDR displays, and WCG-only screens (display-p3, still 8 bit per channel) are not distinguished from SDR. On multi-screen setups (see https://github.com/cmahnke/hdr-canvas/issues/107) re-call this - and the other checks - when the screen changes, e.g. via onDisplayChange, because one-shot results go stale once the window moves to another display.

# KernelExports

Experimental WASM acceleration for Float16Image pixel loops.

Disabled by default: enable explicitly with setWasmEnabled(true). The WASM kernel is inlined as base64 (no .wasm asset URL handling), and every accelerated call falls back to plain JS when WebAssembly is unavailable, denied (e.g. CSP without wasm-unsafe-eval), or fails for any other reason. The WASM path never throws.

Measured reality (Node 24, gain over 12 M values): JS ~12 ms vs WASM ~51 ms with only ~3 ms of that in copies. Engines with native Float16Array convert via hardware F16C instructions that this scalar kernel can't beat, so keep the flag off for gain. The loader stays as tested infrastructure for future compute-heavy kernels where arithmetic intensity amortizes the copy cost.
